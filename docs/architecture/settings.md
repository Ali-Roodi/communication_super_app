# Settings

Part of the architecture notes for this repo. Index and the rules that apply everywhere: [`DEVELOPER_GUIDE.md`](../DEVELOPER_GUIDE.md).

### Settings

Every switch on a settings page is read by something. That was not true, and the ones that were not were **removed, not left on screen**: TTY / hearing-aid / noise-reduction (the whole «دسترس‌پذیری» page), «شناسه تماس‌گیرنده و هرزتماس» (there is no caller-ID database and no spam service — «هرزنامه و مسدودشده» is the thing that actually works), «پاسخ‌های سریع» (the list is now a constant in `incoming_call_screen.dart`; the reject-with-SMS sheet and its «نوشتن پیام...» escape hatch are unchanged), «صدای صفحه‌کلید» and «لرزش هنگام تماس», and «مجوزهای متن‌باز». `SettingsBloc._retiredKeys` drops their SharedPreferences keys once on load so an upgraded install does not carry them.

- **The call ringtone and vibrate-on-ring are Telecom's, not this app's.** It holds the dialer role but never plays the ringer, so «صدا و لرزش» *links* to `ACTION_SOUND_SETTINGS` (`CallHandler.openSoundSettings`, tried-not-probed: `resolveActivity` is filtered by package visibility) instead of offering a switch it could not honour. The two switches left on that page — dialpad tone and dialpad haptic — are both read in `_KeyGrid.press`.
- **«باز کردن صفحه‌کلید هنگام اجرای برنامه» means the app, not the dialer**: the keypad is a bottom sheet opened from the FAB, so app-launch is the only moment there is to pop it. `MainNavigation` does it from the same post-frame callback that consumes the notification deep link (which wins), and skips it when its route is no longer current — an incoming call during launch must not get a modal sheet dropped over it. It reads the flag with `SettingsBloc.readShowDialpadOnStart()` rather than from state, because `LoadSettings` is async and may not have landed by the first frame.
- **«برنامه‌های پیش‌فرض» carries four rows, not two.** Beside the SMS and dialer roles it now lists «اعلان‌های تماس» (`ACTION_APP_NOTIFICATION_SETTINGS`) and «اعلان تمام‌صفحه تماس» (`ACTION_MANAGE_APP_USE_FULL_SCREEN_INTENT`), each with its live state. They are here because `DefaultAppGate` stops asking for them after a few «فعلاً نه»s (see `dialer-and-calls.md`): a grant that decides whether an incoming call can be answered on a locked phone must not become unreachable just because the user silenced the prompt. The four reads run with `Future.wait`.
- **«تماس مجدد خودکار» (`BoolSetting.autoRedial`, `SettingsState.autoRedialAttempts`) is mirrored too** — into `AutoRedialPolicy`, read by `DialerBloc` on a call event. Its page (`AutoRedialPage`) sits under «کمک‌های تماس»; the attempt count is greyed, not hidden, while the switch is off (`SettingsChoice.enabled`), and a stored count outside the offered choices falls back to the default (`AutoRedialPolicy.clampAttempts`). See `dialer-and-calls.md` for what counts as a failed call.
- **«مسدود کردن تماس‌های ناشناس» (`BoolSetting.blockUnknownCallers`) is written twice.** Once to SharedPreferences like every other switch, and once to a native mirror (`NativeCallService.setBlockUnknownCallers` → `CallPrefs`), because the rule is applied in `CallInCallService.onCallAdded` with no Flutter engine. `SettingsBloc` re-asserts it on `LoadSettings` as well as on change. Its UI lives in «هرزنامه و مسدودشده», not on a settings page — it is part of the same question as the blocked list.
- **«رمز برای پاسخ به تماس» (`BoolSetting.pinToAnswerCalls`) is mirrored the same way** (`NativeCallService.setPinToAnswerCalls` → `CallPrefs`), because the incoming card's «پاسخ» is built in `CallInCallService` with no engine. It sits in «امنیت» under «قفل خودکار», only while a PIN is set, in every edition; off by default. What it does is in `dialer-and-calls.md`.
- **«امنیت» gained two rows, both only while a PIN is set, in every edition.** «باز کردن با اثر انگشت یا چهره» (`_BiometricUnlockRow`, see `BiometricUnlock` and docs/DEVELOPER_GUIDE.md) — turning it on raises a real prompt first; the row re-reads on resume (the usual way back here is from the phone's settings after enrolling a finger). «پنهان کردن محتوای اعلان‌ها» (`BoolSetting.hideNotificationContent`, on by default) — mirrored natively as `PIN && switch` by `NotificationPrivacySync`, and applied only while the app is locked (`AppLockSession`); see `sms-role-and-sync.md`.
- **«مسدود کردن تماس»** (`CallBlockRulesPage`) — under «عمومی» and from the top of «هرزنامه و مسدودشده»; see `dialer-and-calls.md`.
- **«پوسته» follows the phone until the user picks one** (`ThemeBloc`, `AppThemeMode.system`): it is the initial state too, so the first frame already paints with the phone's light/dark. «پیش‌فرض گوشی» is listed first. Design decision (1405/07/27).
- **«سیم‌کارت‌ها» (`SimSettingsPage`, under «عمومی», dual-SIM phones only)** — the app's own default card for calls and for SMS: «پیش‌فرض گوشی» (the initial value, which names the card the phone's setting points at right now), a card, or for calls «هر بار بپرس». A contact's or a conversation's own card wins over it; no app can change the phone's own setting. Mirrored natively — see `dual-sim.md`.
- The version row reads `package_info_plus`; a hardcoded string is wrong the first release after it is written and the one place it matters is a bug report.

- **«حریم خصوصی و دسترسی‌ها» (`PrivacyPolicyPage`, under «درباره برنامه») is the store-facing privacy policy, kept inside the app.** It is laid out permission by permission — one card per manifest group saying what the app does with it and what it does not — because that is the question a store reviewer actually asks; the four data-policy sentences from `docs/publishing/store-release.md` follow under «داده‌های شما». Each runtime card shows its live grant state, **read** through `permission_handler` and never requested (the request path is `PermissionGate`'s alone), re-read on every resume because the only place a refused grant can change is the system app-info page the card opens. A permission added to the manifest gets a card there in the same commit; the public-URL copy of the policy is derived from this page, not the other way round.
