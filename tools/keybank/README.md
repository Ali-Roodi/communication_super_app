# ابزار بانک کلید هم‌رسان (سمت مرجع، ویندوز)

این ابزار کلیدهای «پیامک رمز» اعضای یک سازمان را می‌سازد. خروجی آن برای هر عضو یک
**فایل کلید** (`.hkb`) و یک **رمز** است. عضو فایل را در برنامه، در این مسیر وارد می‌کند:
تنظیمات ← بانک کلید ← «وارد کردن فایل کلید».

This tool issues the encrypted-SMS keys of an organization's members. It is
compiled from the app's own crypto source (`android/app/src/main/kotlin/.../smscrypto/`),
so every key file it writes is one the app reads — the JVM tests in
`android/app/src/test/.../smscrypto/keybank/` cover both sides.

## پنل صدور هم‌رسان (برنامهٔ پنجره‌ای)

همین کارها، به‌اضافهٔ ساختن **کد فعال‌سازی نسخهٔ بین‌سازمانی**، در یک برنامهٔ ویندوزی با
فایل نصب `HamresanPanel-1.1.0.msi` هم انجام می‌شود. Java لازم ندارد؛ خودش همراه دارد.

- **کد فعال‌سازی:** کد ۶ نویسه‌ای دستگاه را (گوشی: تنظیمات ← درباره برنامه ← نسخه بین‌سازمانی)
  وارد کنید؛ کد فعال‌سازی فوراً نشان داده می‌شود. این بخش رمز و فایل مرجع نمی‌خواهد.
- **فایل کلید اعضا:** قفل است تا فایل `authority.hka` را انتخاب و رمزش را وارد کنید. بعد
  با فرم «عضو جدید» (نام، شماره، و در صورت تمایل کد دستگاه) عضو به `roster.csv` اضافه
  می‌شود، فایل همه دوباره صادر می‌شود (کلید و رمز قبلی‌ها عوض نمی‌شود) و فایل، رمز و کد
  فعال‌سازی عضو جدید نشان داده می‌شود. «برگهٔ تحویل» یک صفحهٔ چاپی با رمز و مراحل است.
  با کلیک روی هر عضو، رمز و فایل او دوباره دیده می‌شود.
- **چه کسی فایل قدیمی دارد:** هر فایل کلید فهرست کامل اعضا را دارد، پس با هر تغییر فهرست
  فایل بقیه کهنه می‌شود. کنار هر عضو وضعیتش نوشته می‌شود («به‌روز»، «فایل قدیمی»،
  «کلید تازه تحویل نشده»، «تحویل ثبت نشده») و بالای صفحه فهرست کسانی که فایل تازه لازم دارند.
  پنل گوشی‌ها را نمی‌بیند: پس از تحویل، روی عضو بزنید «تحویل داده شد».
- **دفتر صدور:** هر صدور و هر تحویل در `issuance-log.csv` (کنار `authority.hka`) ثبت و در
  برگهٔ «دفتر صدور» نشان داده می‌شود.
- **گوشی گم شد:** کلید و رمز تازه برای همان عضو (`generation` یکی بالا می‌رود). وقتی بقیه
  فایل یا به‌روزرسانی تازه را وارد کنند، گوشی گم‌شده پیام رمز تازه‌ای نمی‌خواند و پیامی از آن
  پذیرفته نمی‌شود. کلیدی که یک بار کنار گذاشته شده، دیگر هرگز صادر نمی‌شود.
- **ویرایش و حذف عضو:** عوض کردن نام و شماره‌ها (با عوض شدن شمارهٔ همراه، کلید عوض می‌شود و
  رمز همان می‌ماند) و حذف از سازمان (فایل و رمز او از `issued` برداشته می‌شود).
- **فایل به‌روزرسانی `update.hku`:** هر صدور کنار فایل‌های اعضا یک فایل به‌روزرسانی هم می‌سازد:
  همان فهرست، بدون کلید هیچ‌کس. برای همه یکی است، **رمز نمی‌خواهد** و فقط گوشی‌ای که قبلاً فایل
  کلید همین سازمان را وارد کرده بازش می‌کند. عضوی که کلیدش عوض نشده می‌تواند به‌جای فایل خودش
  همین را وارد کند (تنظیمات ← بانک کلید ← وارد کردن فایل کلید). کلید تازه فقط در فایل خود عضو است.
- صدور همیشه «همه یا هیچ» است: اگر وسط کار خطایی پیش بیاید، هیچ فایلی عوض نمی‌شود.
- رمز مرجع هیچ‌جا ذخیره نمی‌شود. بخش کلید با دکمهٔ «قفل»، بستن برنامه یا ۱۰ دقیقه کار
  نکردن قفل می‌شود. پیش از هر تغییر، نسخهٔ قبلی `roster.csv` در پوشهٔ `backups` نگه داشته می‌شود.
- پنل همان پوشه‌بندی مراحل زیر را می‌خواهد: `authority.hka`، `roster.csv` و پوشهٔ `issued` کنار هم.

آزمایش نسخهٔ نصب‌شده بدون صفحه:
`HamresanPanel.exe --self-test <پوشه>` نتیجه را در `<پوشه>\self-test.txt` می‌نویسد.

ساختن: `android\gradlew -p tools\keybank :panel:packageReleaseMsi` (با `JAVA_HOME` روی
JDK 21) → `panel/build/compose/binaries/main-release/msi/`.

## پیش‌نیاز (خط فرمان)

Java نسخهٔ ۱۱ یا بالاتر روی ویندوز. فایل‌های `hamresan-keybank.jar` و
`hamresan-keybank.cmd` کنار هم باشند.

## مراحل

**۱. ساختن مرجع (فقط یک بار):**

```
hamresan-keybank init authority.hka
```

رمزی دست‌کم ۱۲ نویسه‌ای می‌خواهد. `authority.hka` کلید امضای مرجع و seed کلید همهٔ اعضا
را دارد: **هر کس این فایل و رمزش را داشته باشد می‌تواند برای کل سازمان کلید صادر کند.**
آن را روی یک رایانهٔ بدون اینترنت نگه دارید و یک نسخهٔ پشتیبان جداگانه بگیرید.
اگر این فایل گم شود، باید برای همه کلید تازه صادر شود.

**۲. تحویل کلید عمومی مرجع به تیم برنامه (فقط یک بار):**

```
hamresan-keybank public authority.hka
```

خط هگز طولانی خروجی را به تیم برنامه بدهید تا داخل برنامه قرار بگیرد
(`lib/features/keybank/services/trust_anchors.dart`). این کلید محرمانه نیست؛ برنامه با
آن فقط امضا را بررسی می‌کند و نمی‌تواند چیزی امضا کند.

**۳. فهرست اعضا (`roster.csv`)** — در Excel با «CSV UTF-8» ذخیره کنید:

```
organization,نام سازمان
name,phones,generation
علی رضایی,09121111111;02188776655
مریم احمدی,09122222222
```

- خط `organization` نام سازمان است که در برنامه نمایش داده می‌شود.
- چند شماره را با `;` از هم جدا کنید. شماره در هر شکلی قابل قبول است (`+98…`، `0912…`، ارقام فارسی).
- `generation` اختیاری است (پیش‌فرض ۰). اگر گوشی عضوی گم شد، این عدد را یکی زیاد کنید:
  کلید تازه‌ای برای او ساخته می‌شود و کلید قبلی دیگر در دفترچه نیست.
- کلید هر عضو از **اولین شماره‌اش** و `generation` او ساخته می‌شود؛ ترتیب شماره‌ها را عوض نکنید.

**۴. صدور فایل‌ها:**

```
hamresan-keybank issue authority.hka roster.csv out
```

برای هر عضو یک فایل `out\NNN-<شماره>.hkb` و در `out\passwords.csv` رمز آن را می‌سازد،
و `out\update.hku` (فایل به‌روزرسانی بدون رمز برای اعضای فعلی؛ بالا را ببینید).
فایل و رمز را **از دو راه جدا** به عضو بدهید (مثلاً فایل روی فلش، رمز حضوری).

صدور دوباره از همان فهرست (مثلاً بعد از اضافه شدن عضو جدید) کلید هیچ عضو قبلی را عوض نمی‌کند
و رمزهای موجود در `passwords.csv` دوباره استفاده می‌شوند. دفترچهٔ جدید تاریخ جدیدتری دارد و
برنامه نسخهٔ قدیمی‌تر را جایگزین آن نمی‌کند.

**۵. بررسی یک فایل (اختیاری):**

```
hamresan-keybank inspect out\001-09121111111.hkb authority-public.txt
```

`authority-public.txt` همان خط هگز مرحلهٔ ۲ است.

**۶. کد فعال‌سازی (بدون مرجع):**

```
hamresan-keybank activation 4f339b
```

کد فعال‌سازی نسخهٔ بین‌سازمانی را برای کد دستگاه چاپ می‌کند.

## نکته‌ها

- برای دیدن درست متن فارسی در پنجرهٔ فرمان، از `hamresan-keybank.cmd` استفاده کنید؛
  این فایل خودش `chcp 65001` را اجرا می‌کند.
- برای اجرای خودکار، رمز مرجع را می‌توان در متغیر محیطی `HAMRESAN_KEYBANK_PASSWORD` داد.

## ساختن ابزار (برای تیم برنامه)

```
android\gradlew -p tools\keybank jar
```

خروجی: `tools/keybank/build/libs/hamresan-keybank.jar`. پوشهٔ `dev/` مرجع **آزمایشی**
توسعه است: کلید خصوصی دارد و وارد git نمی‌شود. برنامه فقط وقتی به آن اعتماد می‌کند که با
`--dart-define=HAMRESAN_DEV_ANCHOR=true` ساخته شده باشد.
